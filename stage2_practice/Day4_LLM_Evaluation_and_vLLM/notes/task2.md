# 把大象装进冰箱

## 1. 先准备自己的数据

第一步是把测试集整理成一个文件。

比如新建：

```text
custom_dataset/test.jsonl
```

每一行放一条题目。

普通问答可以这样写：

```json
{"id":"001","question":"中国的首都是哪里？","answer":"北京"}
{"id":"002","question":"1+1等于几？","answer":"2"}
```

代码生成任务可以这样写：

```json
{"id":"001","prompt":"def is_palindrome(s):","test":"assert is_palindrome('aba') == True"}
```

我的理解是，这一步的重点是把题目、答案、测试用例都保存清楚。

格式不一定要多复杂，但一定要统一。

比如都用 `question` 表示题目，就不要一会儿写 `question`，一会儿写 `query`。

剩下的字段怎么解释，就交给后面的 adapter 来处理。

## 2. 决定怎么问模型

有了数据之后，还要把每条数据变成模型真正看到的问题。

比如原始数据是：

```json
{"question":"实现一个回文判断函数"}
```

可以拼成：

```text
请根据下面的要求写一段 Python 代码。
要求：实现一个回文判断函数。
只输出代码。
```

这一步就是 prompt 构造。

它的作用是告诉模型要做什么，也告诉模型应该怎么回答。

如果 prompt 写得清楚，模型的输出一般会更稳定。

比如代码题里加一句“只输出代码”，就可以减少解释、markdown 和其他无关内容。

这对后面的自动评分也更友好。

## 3. 写一个 adapter 文件

接下来需要写一个 adapter 文件。

可以把 adapter 理解成一个“翻译器”。

它负责把自己的数据格式转成 EvalScope 能处理的格式。

比如新建：

```text
custom_adapter.py
```

里面主要做几件事：

```text
读取 test.jsonl
拼接 prompt
处理模型输出
计算单条样本的分数
汇总所有样本的结果
```

大概会有这些逻辑：

```python
load_dataset()
build_prompt()
post_process()
compute_score()
aggregate()
```

我的理解是，adapter 要告诉 EvalScope 每个字段是什么意思。

比如：

```text
从 question 字段拿题目
从 answer 字段拿标准答案
把题目整理成 prompt
把模型回答和标准答案进行比较
最后把所有题目的分数汇总起来
```

没有 adapter 的话，EvalScope 不知道你的数据该怎么读，也不知道答案该怎么算对。

## 4. 定义评分方式

评分方式要看任务类型。

如果是选择题，就直接比对选项。

```text
模型输出 A
标准答案 A
结果正确
```

如果是普通问答，可以做字符串匹配。

```text
模型答案里包含标准答案
就认为正确
```

如果是代码生成，就执行测试用例。

```text
模型生成代码
运行 assert 测试
全部通过就算正确
```

这一部分很重要。

因为 benchmark 最后看的不是模型“看起来答得怎么样”，而是要有一个明确的分数。

所以这里需要定义单条样本怎么算分。

比如：

```text
正确：1
错误：0
```

或者：

```text
完全匹配：1
部分匹配：0.5
错误：0
```

不同任务可以用不同指标。

比如：

```text
选择题：accuracy
代码生成：pass@k
问答任务：exact match 或 F1
开放式问答：人工规则或 judge 评分
```

## 5. 做 aggregate 汇总

之前漏掉了。

单条题目算完分之后，还需要把所有题目的结果汇总成最终指标。

比如有 100 道题，其中 80 道答对。

那么最终 accuracy 就是：

```text
80 / 100 = 0.8
```

如果是 pass@k，也需要把每道题多次生成的结果合在一起看。

比如一道题生成 3 次，只要其中 1 次通过测试，这道题的 pass@3 就算通过。

最后再对所有题目求平均。

所以 aggregate 做的事就是：

```text
收集每道题的分数
计算平均分
生成最终报告
```


## 6. 注册这个 benchmark

写好 adapter 后，还需要让 EvalScope 知道这个测试集叫什么。

比如注册成：

```text
custom_code
```

这样之后就可以用命令调用：

```bash
evalscope eval \
  --datasets custom_code
```

如果不注册，EvalScope 就不知道 `custom_code` 对应哪个数据集，也不知道该用哪个 adapter。

## 8. 简单总结


这件事整体不算难。

如果是选择题或标准问答，比较好做。

如果是代码生成，主要难在测试用例要写清楚。

如果是开放式问答，主要难在评分标准不好定。
